Connect a private Google Sheet

Save your selected vocabulary, manual meanings, articles, plurals, examples, and source links to a private spreadsheet. Sign in and open the same spreadsheet to load your vocabulary on your next visit.

1. Configure your Google project

  1. Open the Google Cloud console with your personal Google account and create a project named LearnGerman (or use an appropriate existing project).
  2. Under APIs & Services → Library, enable Google Sheets API.
  3. Open Google Auth Platform. Set the app name and your support/contact email. For a personal Google account, choose an External audience. While testing, add your own account as a test user.
  4. In Data Access, add the scope https://www.googleapis.com/auth/drive.file. The app only needs access to files created or explicitly selected through it.
  5. Under Clients, create an OAuth client of type Web application. Add http://localhost:4173 to Authorized JavaScript origins. The host and port must match exactly; do not use a URL path.
  6. Copy the Client ID, ending in .apps.googleusercontent.com. Do not copy a client secret or download account credentials into the project.

We will add your actual GitHub Pages origin when the repository and deployed address exist. No paid AI service or service-account key is needed for this test.

2. Save and reload your vocabulary

  1. Open http://localhost:4173 in Chrome or Edge, expand Google Sheets verbinden, paste the Client ID, and click Mit Google verbinden. Choose the Google account you added as a test user.
  2. For the first vocabulary save, click Neue Vokabeltabelle erstellen once. This creates LearnGerman — Wortschatz, separate from the old connection-test sheet. Creation alone does not save your selection.
  3. In Meine Auswahl, click In Google Sheets speichern. Wait for the message confirming that the data was saved and read back. Removing a meaning is also a pending change until you save. You can undo the last removal.
  4. Keep the resulting spreadsheet link. Optionally check Client-ID und Tabellenlink auf diesem Gerät merken. Only these settings are kept locally; no login token is stored.
  5. On your next visit, sign in again, paste the same spreadsheet link (or use the remembered one), then click Tabelle öffnen. This loads your saved vocabulary. Gespeicherte Auswahl laden fetches newer changes from another device without discarding your pending local changes.
  6. For a recovery copy, use Auswahl herunterladen. Auswahl aus Datei ergänzen merges an exported selection without clearing existing words. Imports must then be saved to Google Sheets.

The pasted link can reopen a vocabulary spreadsheet already created by this app with the same Google project/account. It does not grant access to an arbitrary existing spreadsheet. Keep sharing Restricted.

Save/load is explicit, not automatic. Unsaved changes and manual drafts remain only in this page until saved or exported. A failed save keeps them pending; retrying checks what reached Google first. If creating a new spreadsheet times out, check Drive before creating another.

The spreadsheet contains an application-managed change history. Do not edit, sort, or delete its rows directly. Manage vocabulary through the app. Concurrent changes to different words are merged; for the same meaning, the last unique change appended to the history wins. This first release does not include background sync, sets, practice, or offline storage.

3. Optional connection test

  1. Return to the app at http://localhost:4173 and expand Google Sheets verbinden.
  2. Paste the OAuth Client ID and click Mit Google verbinden. Select your account in Google's dialog and grant file access.
  3. Expand Verbindungstest mit Beispielwort and click Testtabelle erstellen once. This creates a file named LearnGerman — Verbindungstest in your Drive and checks the saved example row. It is separate from your vocabulary table.
  4. Open the returned link and confirm that Sharing is Restricted. Use Testzeile lesen to repeat the read without creating another file.

Tokens remain in memory and disappear when this page closes or you disconnect. The test sheet remains in your Drive. Reloading resets this prototype's sheet selection; check Drive before creating another test sheet.

If creation times out, first check Drive for a newly created file. A lost response does not prove the creation failed. Do not repeatedly click Create.

4. GitHub Pages and other devices

The same email address and OAuth Client ID can be used after deployment. In Google Auth Platform → Clients, add your deployed site's origin (for example https://YOUR-USERNAME.github.io) to Authorized JavaScript origins. Do not include the repository path. Keep localhost as another origin for development. If the app remains in Testing mode, keep your account in Audience → Test users.

Sign in on each device with the same account and open the same app-created spreadsheet. Settings remembered on localhost do not transfer to GitHub Pages or to another device; enter the Client ID and spreadsheet link there once. The spreadsheet stays private even when the application source is public. GitHub Pages deployment and live cross-device access have not yet been verified.

5. If something does not work

  • Origin mismatch: check that the OAuth client has the exact origin http://localhost:4173, without a trailing path.
  • Access denied: check the test-user list, selected Google account, requested scope, and enabled Sheets API.
  • Popup blocked or expired connection: allow Google's sign-in popup, then click Connect again.
  • Unverified app notice: confirm that it identifies your own project and the expected file permission. Do not proceed if it is an unfamiliar project or requests unexpected access.

Google's testing mode and token lifecycle can require renewed consent. This needs validation on your account before the app is used daily.
